BAGIAN I — RINGKASAN PROGRES PERTEMUAN 1: PLANNING & ARCHITECTURE

1. Latar Belakang, Problem Statement & Target SLA

Trafik War Tiket memiliki karakteristik flash crowd, di mana ribuan pengguna mengirim permintaan transaksi dalam detik yang sama. Arsitektur konvensional berisiko mengalami crash OOM, kegagalan transaksi, dan race condition (overselling). Proyek ini merancang solusi terorkestrasi berbasis Docker Swarm dengan sasaran SLA ketat: Latency < 200ms, Error Rate < 1%, serta 0% Overselling di bawah batasan komputasi lokal 0.25 CPU dan 256M RAM per container.

9. Identifikasi Single Point of Failure (SPOF) Saat Ini

SPOF (*Single Point of Failure*) adalah titik tunggal dalam arsitektur yang apabila mengalami kegagalan proses/koneksi, berpotensi melumpuhkan seluruh fungsionalitas sistem. Analisis titik SPOF pada arsitektur klaster kami:

Komponen Service Status Replikasi Klasifikasi SPOF Dampak Jika Terjadi Kegagalan Container
Backend API (app) replicas: 2 (Scalable s.d 8) Bukan SPOF Toleran terhadap kegagalan. Jika 1 worker mati, request langsung dialihkan ke worker lain tanpa downtime.
Reverse Proxy (nginx) replicas: 1 Titik SPOF 1 Jika Nginx mati, seluruh akses HTTP dari klien eksternal terputus total.
Datastore (redis) replicas: 1 Titik SPOF 2 Jika Redis mati, endpoint checkout tiket menolak transaksi (HTTP 500) demi mencegah data minus.

10. Mitigasi Level 1 yang Sudah Diterapkan (Tahap Saat Ini)

Pada tahapan Pertemuan 2, sistem telah dilengkapi mekanisme mitigasi dasar untuk meredam dampak kegagalan:

  • Self-Healing Otomatis Docker Swarm: Konfigurasi restart_policy: condition: on-failure memastikan bahwa jika container Redis atau Nginx mengalami crash mendadak, Docker Swarm akan langsung men-spawn ulang container baru dalam hitungan detik.
  • Data Persistence (AOF & Volume): Redis dikonfigurasi dengan flag --appendonly yes yang dipetakan ke volume Docker redis-data:/data. Saat Redis hidup kembali, seluruh riwayat transaksi dan sisa stok tiket tetap utuh (zero data loss).
  • Fail-Safe API Circuit Breaker: Driver ioredis dikonfigurasi dengan enableOfflineQueue: false dan blok try-catch aman. Saat Redis mati, transaksi langsung ditolak dengan HTTP 500 (Fail-Safe), sehingga tidak terjadi transaksi gantung atau overselling. Driver otomatis melakukan rekoneksi saat Redis kembali aktif.

11. Roadmap Solusi High Availability Sejati (Level 2: Rencana Lanjutan)

Untuk mengeliminasi titik SPOF secara mutlak menuju arsitektur High Availability (HA) sejati pada pertemuan lanjutan:

Titik SPOF Solusi Arsitektur HA yang Direncanakan Mekanisme Kerja Failover
Nginx Ingress Multi-Replica Nginx Ingress & Swarm Routing Mesh Menaikkan replika Nginx menjadi 2 instance. Port 80 dipublikasikan melalui Swarm Ingress Routing Mesh, sehingga kegagalan satu Nginx tidak memutus akses klien.
Redis Datastore Redis Sentinel Architecture (Master-Replica) Mengonfigurasi 1 Redis Master untuk penulisan stok, 1 Redis Replica untuk sinkronisasi data, dan Redis Sentinel untuk promosi failover otomatis tanpa downtime.
