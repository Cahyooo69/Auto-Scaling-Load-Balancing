3. Verifikasi Penerapan Resource Limits

Ketentuan standar tugas besar 3 SKS mewajibkan pembatasan sumber daya ketat pada setiap container:

  • Maksimal CPU: 0.25 core (maksimal 25% dari 1 core CPU host).
  • Maksimal Memori RAM: 256 MB (268.435.456 Bytes).
  • Reservasi Sumber Daya: 0.10 core CPU dan 64 MB RAM.

Penerapan batasan ini diverifikasi langsung dari Docker Daemon menggunakan perintah inspeksi metadata tugas Swarm:

Service Spesifikasi Limit (Compose) Nilai Inspeksi Kernel (Docker Inspect) Status Kepatuhan

Load Balancer (wartiket_nginx) CPU: 0.25 | RAM: 256M NanoCPUs: 250000000 | MemoryBytes: 268435456 Memenuhi Standar
Database Redis (wartiket_redis) CPU: 0.25 | RAM: 256M NanoCPUs: 250000000 | MemoryBytes: 268435456 Memenuhi Standar
Bukti Eksekusi Terminal (Docker Inspect):
$ docker service inspect wartiket_app --format "{{json .Spec.TaskTemplate.Resources}}" {"Limits":{"NanoCPUs":250000000,"MemoryBytes":268435456},"Reservations":{"NanoCPUs":100000000,"MemoryBytes":67108864}}
Keterangan: Nilai 250.000.000 NanoCPUs setara tepat dengan 0.25 CPU Core, dan 268.435.456 Bytes setara tepat dengan 256 MB RAM.

4. Skema Jaringan Internal & Uji Konektivitas

Seluruh container terhubung di dalam jaringan internal bertipe Docker Overlay Network dengan konfigurasi berikut:

  • Nama Jaringan: wartiket_wartiket-net (Driver: overlay, Scope: swarm).
  • Alokasi Subnet: 10.0.1.0/24 dengan gateway internal otomatis.
  • Isolasi Port: Port backend (3000) dan port database (6379) tidak dipublikasikan ke host, sehingga hanya dapat diakses melalui jaringan internal oleh Nginx.
  • Service Discovery & VIP: Nginx me-resolve nama host app:3000 melalui DNS internal Docker Swarm (127.0.0.11).
$ docker network inspect wartiket_wartiket-net --format "Driver: {{.Driver}} | Scope: {{.Scope}} | Subnet: {{range .IPAM.Config}}{{.Subnet}}{{end}}" Driver: overlay | Scope: swarm | Subnet: 10.0.1.0/24

5. Pengujian Fungsional End-to-End Jaringan

Untuk membuktikan bahwa seluruh container tidak hanya berjalan tetapi juga saling terhubung secara fungsional (*end-to-end*), telah dilakukan pengujian transaksi bersamaan melalui port 80 Nginx menggunakan skrip penguji:

Kesimpulan Hasil Pengujian Fungsional:
  1. Konektivitas Nginx → Backend: Berhasil 100%. Request dari port 80 diteruskan dan dibagi seimbang 50:50 (10 request ke Worker 1 dan 10 request ke Worker 2).
  2. Konektivitas Backend → Redis: Berhasil 100%. Transaksi checkout berhasil mengeksekusi script Lua atomic decrement di Redis, terbukti dari sisa stok yang tereduksi konsisten dari 999 ke 980.
  3. Target SLA: Seluruh respon memiliki latency rata-rata ∼95ms, jauh di bawah batas maksimum SLA yaitu 200ms.
